# 管理端与 AI 集成开发说明

用户担任组长，明确负责管理端 Web（MVC）、实时看板、多维统计图表和 AI 推理服务集成。本轮在 `feat/admin-ai-first-iteration` 分支推进第一条可运行的集成链路。

## 本轮完成范围

| 功能           | 当前实现                                                        | 验证边界                                       |
| -------------- | --------------------------------------------------------------- | ---------------------------------------------- |
| 管理端 MVC     | 展示、控制器、模型、仓储分层，独立 HTTP 与身份适配              | 前端构建与类型检查                             |
| 登录与角色界面 | API 登录、会话恢复、401 退出；教师隐藏用户目录和 AI 操作        | 本地合成账号；正式账号系统仍由后端实现         |
| 课堂数据与安排 | 接口读取数据、管理员安排学生、刷新保留安排                      | 独立联调 SQLite；不修改正式业务后端            |
| 实时看板       | WebSocket 事件驱动刷新，失败重连与 5 秒轮询，显示连接和同步状态 | 本地真实网络服务；不是模拟 UI 定时增加数字     |
| 多维统计       | 按课堂、课程、班级、起止日期时间过滤，情绪分布与实际时间趋势    | 前端基于授权范围内已加载记录聚合               |
| CSV            | 导出当前筛选记录，转义危险公式和引号，包含模拟输入标记          | 浏览器及联调导出分别验证                       |
| AI 集成        | 受保护启停、采样频率与阈值配置、七种模型表情映射                | 模拟输入完成集成验证；真实模型适配通过替身测试 |
| 上报可靠性     | 独立令牌、持久化结果队列、指数退避、幂等键、错误状态            | 网络故障替身测试与联调实际入库                 |
| 匿名化         | 不上报用户编号，不存原始帧、人脸图片或特征                      | 代码与请求契约检查；不自动启用摄像头           |

## 一条命令启动联调

首次准备：

```powershell
npm ci
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r services/integration/requirements.txt -r services/ai/requirements.txt
```

之后从项目根目录运行：

```powershell
npm run dev:integration
```

- 管理端：<http://127.0.0.1:5175>。
- 参考服务与 Swagger：<http://127.0.0.1:8010/docs>。
- AI 健康检查：<http://127.0.0.1:8011/health>。
- 合成账号 `admin` 或 `teacher`，密码均为 `integration-only`。它们仅存在于本机联调服务，不能用于正式部署。
- 管理员可查看两门合成课程；教师只能查看自己的第一门课程。第二门课程用于验证越权隔离。
- 在“AI 集成”页选择课堂，保持“模拟输入”，设置采样间隔和阈值后启动。切换“课堂概览”或“情绪记录”，无需手动刷新即可看到匿名结果。记录显示“AI 模拟”，不会冒充真实分析。
- 模拟周期包含低置信度样本，用于验证过滤计数。初始数据没有任何情绪记录，只有明确启动后才产生结果。
- 点击停止后，已入库记录保留；待重试结果也保留。停止时若真实推理未返回，状态保持采集中，等待当前推理结束再释放摄像头。
- `Ctrl+C` 关闭启动脚本管理的三个子进程。端口冲突会明确报错，不会悄悄更换端口。

启动脚本每次生成独立入库令牌和控制令牌，通过子进程环境传递，不写入仓库或页面。管理端只携带登录后的用户令牌，AI 控制请求由参考服务代理。

`.local/integration.sqlite` 保存合成课堂安排和结构化结果；`.local/ai-outbox.sqlite` 保存待重试结构化结果。两个文件均已忽略，不提交到 Git。重启服务会保留数据，但需重新登录；页面模式不同，登录存储也互相隔离。

## 正式后端协作边界

`services/backend` 仍是团队的正式后端。本轮不替队友实现完整账号、课程 CRUD 或正式业务持久化。`services/integration` 是单独运行、仅允许回环访问的本地参考服务，要求显式 `MOOD_INTEGRATION=1` 才能启动，严禁作为线上后端。

正式后端负责人需按 `docs/api-contract.md` 补齐登录响应、权限、可见课堂、历史、安排、AI 入库、WebSocket 短票据和 AI 控制代理接口。前端改为 `VITE_DATA_MODE=api`、配置后端地址后即可沿同一仓储适配层接入。接口不匹配会明确显示错误，不回退到演示成功。

正式权限必须在服务端校验：管理员管理用户与安排，教师只能访问所授课堂看板与统计，AI 服务令牌不能当成用户令牌。正式账号注册、管理员受控创建和修改密码仍依赖团队后端；本轮登录页不提供不安全的管理员自助提权。

正式后端 AI 入库应采用数据库唯一约束实现 `Idempotency-Key` 去重，并在同键不同载荷时拒绝。AI 上报成功响应须为 `data.accepted: boolean`；拒绝低置信度时返回 `accepted: false`，避免发送端误判成功。默认拒绝 `simulated: true`，正式数据库不混入联调模拟数据。

实时通道采用登录态换取一次性、30 秒有效票据，再以票据连接 `/ws/dashboard`。票据只能使用一次；连接沿用用户可见课堂范围，退出登录后关闭通道。URL 不携带可复用访问令牌。事件只通知刷新，不直接把全局用户数据广播给教师。

管理端当前加载完整可见记录再聚合，适合课程实验规模。正式后端加入分页时，必须同步提供服务端聚合结果并修改仓储和图表，不能只统计某一页后宣称是全量统计。日期时间范围采用本机时区输入、时间戳比较，起点包含、终点不包含。

## 真实摄像头与模型

本轮不会自动开启用户摄像头。真实模型路径已实现，但没有真实视频、模型权重与运行环境的实测结果，不能据此声称 AI 已验收。

建议创建独立、与 TensorFlow 兼容的 Python 环境安装：

```powershell
python -m pip install -r services/ai/requirements-model.txt
```

若使用另一套 Python 运行 AI 服务，在启动联调前设置 `AI_PYTHON_EXECUTABLE` 为该环境的 Python 可执行文件绝对路径。基础联调不依赖 OpenCV、TensorFlow 或模型下载。实际兼容性应在选定平台上验证，不能把本机 Python 3.13 的模拟测试视为真实模型兼容性结论。

真实模式调用 DeepFace 的 `analyze`，仅请求 `actions=['emotion']`，启用人脸检测，不做身份识别、年龄、性别或种族分析。默认 OpenCV 检测，分数除以一百转换为零至一；人脸未检出时无结果，不用背景图像伪造人脸结果。摄像头断线会重试连接，其他模型加载错误会显示失败状态。

官方接口与类别依据：[DeepFace 官方项目](https://github.com/serengil/deepface)、[官方表情分析实现](https://github.com/serengil/deepface/blob/master/deepface/modules/demography.py)。真实模型首次运行可能下载模型权重；原始视频帧不传到外部推理服务。

| 模型表情 | 系统枚举  | 界面含义 |
| -------- | --------- | -------- |
| happy    | HAPPY     | 开心     |
| neutral  | NEUTRAL   | 平静     |
| sad      | SAD       | 低落     |
| angry    | ANGRY     | 生气     |
| surprise | SURPRISED | 惊讶     |
| fear     | FEAR      | 害怕     |
| disgust  | DISGUST   | 厌恶     |

`FOCUSED`、`CONFUSED` 保留给手动反馈。表情分数不等于心理状态或学习效果，受遮挡、光照、角度、群体差异、检测遗漏和模型偏差影响。AI 记录是按采样检测的人脸结果，不能用条数当作去重学生人数。本轮不做跨帧身份追踪。
