# 客户端与后端对接约定

客户端负责学生账号、课堂选择、手动反馈、个人历史，以及教师所授课堂和相关学生历史与基础统计。实时看板、多维统计、CSV 和用户安排由管理端提供，AI 控制不属于客户端。

本约定补充 [客户端任务交接](client-handoff.md)，正式共享合同以 [API 契约](api-contract.md)、确认后的共享类型和实际 OpenAPI 为准。本文件包含已知合同与待确认事项，不能将待确认的内容视作已实现接口。客户端现已提供两种仓储和完整页面；正式后端业务仍为占位，实际 HTTP 核对见 [客户端验证结果](client-test-report.md)。

## 接口范围

JSON 采用小驼峰，受保护接口携带 Bearer 令牌，注册和登录不要求已有令牌；响应为 `{code,message,data}`，成功 `code: "OK"`，错误按 HTTP 状态和业务码处理。客户端不公开注册管理员，不读取全局用户目录。

| 接口                                    | 已知请求或数据                                                | 客户端处理与待确认内容                                                                             |
| --------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| POST /api/auth/register                 | username、email、password、role；role 只允许 STUDENT／TEACHER | 注册成功后进入登录，不依赖未约定的成功 data；教师授予／审批流程需确认                              |
| POST /api/auth/login                    | username、password；成功 data 为 `{token,user}`               | 使用共享 AuthSession／User；明确过期、禁用和教师待审核行为                                         |
| GET /api/users/me                       | 当前身份，User                                                | 恢复登录并检查角色；失效后清理登录态和个人数据                                                     |
| PUT /api/auth/password                  | oldPassword、newPassword                                      | 成功只依赖 OK；需确认哪些会话被撤销及是否重新登录                                                  |
| POST /api/auth/logout                   | 当前用户认证                                                  | 撤销当前会话；客户端清理数据并中止旧请求；网络失败时提示服务端注销未确认                           |
| GET /api/sessions                       | 当前用户可访问课堂，列表 data 为数组                          | 学生按安排名单、教师按任课范围；正式字段见共享 ClassSession，确认课堂状态和开放提交时间            |
| POST /api/emoji                         | 仅 `{sessionId,emotion}`                                      | 后端确定 userId、MANUAL 和记录时间；提交成功需已持久化；成功后重新读历史，不依赖未约定的写响应字段 |
| GET /api/emoji/history?sessionId=...    | 当前身份可见历史，列表 data 为数组                            | 学生仅本人；教师仅所授课堂与相关学生。默认排序、范围和数量限制需明确                               |
| GET /api/emoji/statistics?sessionId=... | 教师当前课堂基础统计                                          | 正式成功 data 尚未确定；候选结构见下一节                                                           |

公开注册的用户名长度为 2–50，密码为 8–128；邮箱格式和重复账号错误由后端明确并强制校验。教师注册要求需要可执行的角色授予流程，不能仅依据注册请求中的 TEACHER 字段直接获得权限。

课堂编号是 UUID。手动提交示例仅用于说明请求合同：

```json
{
  "sessionId": "11111111-1111-4111-8111-111111111111",
  "emotion": "CONFUSED"
}
```

学生不提交 userId、source、confidence、deviceId 或 AI 元数据。情绪使用 packages/contracts 的九种枚举；FOCUSED 和 CONFUSED 仅为手动反馈。接口收到额外敏感字段时应拒绝或按明确合同处理，不能用它们覆盖登录身份。

## 需要冻结的业务与响应

| 事项         | 客户端初始方案                                       | 后端需要确认                                                   |
| ------------ | ---------------------------------------------------- | -------------------------------------------------------------- |
| 学生获得课堂 | 管理员预安排名单；无课堂时给出提示                   | 名单过滤、课堂创建／初始化方式                                 |
| 可提交时段   | 页面根据同一课堂规则显示可提交状态                   | 课前／课后策略；拒绝的 HTTP 状态和业务码                       |
| 多次反馈     | 请求期间禁用提交；网络失败保留选择；写请求不自动重放 | 同一学生一节课多次新增还是覆盖；超时后如何查证或幂等重试       |
| 个人记录     | 学生仅本人手动记录                                   | 服务端过滤；匿名 AI 不归入学生个人历史                         |
| 教师相关学生 | 在所授课堂范围显示和筛选                             | 课堂内有限身份字段或授权名单；不得依赖管理员用户目录           |
| 历史列表     | 沿用数组响应，客户端不新增服务端分页合同             | 默认排序、范围、上限；有截断必须显式声明，增加分页须同步调用方 |
| 教师基础统计 | 当前课堂总记录数和各情绪分布                         | 分母、MANUAL／AI 合并或区分策略、全量聚合与返回格式            |
| 时间         | 带时区的 ISO 8601；区间为 `[from,to)`                | 支持哪些查询参数，时间解析和非法区间错误                       |
| 管理端入口   | 配置地址，进入后可再次登录                           | 如需统一登录，另行约定同源部署或服务端会话方案                 |

基础统计候选数据为 `{total:number,distribution:Record<Emotion,number>}`，完整列出九种情绪并以零表示无记录；分母为相同范围和来源的记录条数。它参考独立联调服务的管理端统计实现，尚不证明正式 `/api/emoji/statistics` 接受此合同。确认后同步 API 文档、共享类型和客户端适配。

教师按学生查看时，匿名 AI 记录单独标识。需要显示姓名时由授权的课堂名单或记录扩展提供有限字段；具体方案与后端一起冻结，不新增未经约定的 API 路径。

## 错误与数据一致性

- 401：清理失效身份和个人数据，提示重新登录；登录密码错误显示表单错误。
- 403：提示当前课堂或操作无权限，不回退到全量数据。
- 404、409、422：显示可理解的业务提示；重复账号、课堂不可用、非法提交等具体业务码由后端给出样例。
- 501、503、超时、断网或非 JSON 响应：保持失败状态，不使用演示数据替代真实请求结果。
- 退出时立即清除本地个人状态；服务端注销失败须与本地退出区分。课堂快速切换、退出及换号后，旧响应不得覆盖当前状态。
- 手动提交成功必须代表数据库提交完成。响应丢失时结果可能未知，不能简单断言未入库并无限重试。
- 前端隐藏菜单不代替后端鉴权；历史、课堂、统计与提交均须按真实身份限制范围。

## 后端联调交付

后端提供可用地址、对应版本 OpenAPI、初始化与重置测试数据的方法，以及以下合成数据：两名学生、两名具有不同任课范围的教师、管理员和至少两节课堂，明确谁被安排到哪个课堂。真实密码和令牌单独交付，不提交 Git。

至少给出登录、本人信息、课堂列表、提交后历史、基础统计的成功样例，以及 401、403、409、422 和未开放课堂的错误样例。注册、改密和注销如不返回业务数据，统一包装中的 data 可按合同为空，客户端不强制假定其他内容。

先联调“登录 → 选择真实课堂 → 提交 → 个人历史”，再覆盖注册改密、教师视图、管理端一致性和权限边界。具体用例见 [客户端验收清单](client-acceptance.md)。

## 变更与交付反馈

接口变化先明确请求、响应、数据范围、错误码和受影响调用方；确认后同步共享类型、API 文档、客户端仓储、mock 和测试。参考服务不能代替正式后端验收。

交付反馈至少包含：所测提交、服务版本、环境模式、复现步骤、预期与实际、HTTP 状态及脱敏响应、影响和维护模块。客户端缺陷由客户端修复，后端持久化及权限缺陷由后端维护者修复，修复后共同回归。
