# 系统验收

验收将客户端、管理端 API 模式的生产构建、正式 FastAPI 后端、真实 PostgreSQL 和独立 AI 服务连接起来。数据全部为合成账号；AI 使用带 `simulated` 标记的结构化输入，与正式数据隔离。演示页面、参考联调服务和模型替身不作为真实模型或设备的通过依据。

## 可重复运行

先执行 `npm ci`，创建 `.venv` 并安装 `services/backend/requirements-dev.txt` 与 `services/ai/requirements.txt`。安装浏览器：`npx playwright install chromium`；Linux 缺少系统库时使用 `--with-deps`。需要 Node.js 22.12 以上、Python 及真实 PostgreSQL 测试服务器；推荐版本与 CI 一致，为 Node.js 24、Python 3.13、PostgreSQL 17。

```bash
export MOOD_TEST_DATABASE_URL='postgresql+psycopg://<测试账号>:<测试密码>@127.0.0.1:5432/postgres'
npm run test:system
```

PowerShell 用 `$env:MOOD_TEST_DATABASE_URL = '...'` 设置变量。脚本优先使用仓库 `.venv` 的 Python，也可通过 `MOOD_TEST_PYTHON` 指定解释器。测试账号须有创建数据库权限；脚本只创建、迁移和删除随机临时库，不清空变量指向的数据库。未设置该变量时明确失败，不以跳过当作通过。使用随机空闲端口、随机服务令牌和独立临时 AI 队列，不调用付费 API、不启动摄像头。

容器验收使用同一浏览器流程：

```bash
npm run test:system -- --runtime compose
```

此模式需要可用的 Docker Engine 和 Compose，自动构建镜像、运行迁移与 Nginx 代理；无需外部测试数据库。随机项目名和独立数据卷隔离日常环境，不读取根 `.env`。结束后清理本次容器和卷。测试数据库、相机和公开图片不会混用。

产物在被忽略的 `.local/acceptance/`：`report.json` 区分运行模式与通过状态，诊断日志仅本地保存。临时数据库与 AI 队列正常退出时清理；异常强制终止后需确认原进程已退出，才可删除 `running.lock` 并清理以 `mood_acceptance_` 开头的孤立测试库。单次运行不允许并发覆盖同一产物目录。

## 自动化覆盖

| 范围       | 验证                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 账号与角色 | 页面学生注册、登录与刷新；教师申请未经审批拒绝登录，批准后可用；公开注册不能创建管理员                           |
| 课堂与隔离 | 管理员真实安排名单；学生只看本人课堂；两学生互查与跨课堂提交拒绝；教师跨任课范围及导出拒绝                       |
| 手动反馈   | 真实页面提交，记录身份与来源一致；断网不显示保存；丢失成功回执后使用同键重试只保留一条                           |
| 跨端一致   | 同一记录 ID 出现在学生历史、任课教师历史和管理员 CSV；统计按完整数据计算                                         |
| 统计与 CSV | MANUAL / AI / ALL 来源；分布、时间趋势、分组总数一致；10 行分页导出 12 条匹配记录，BOM、公式防护和自评分类型保留 |
| 实时与控制 | 短票据 URL、最小通知载荷、WebSocket 连接；实际 AI 服务模拟启停、教师自动刷新、课程资料版本变化、注销关闭自身通道 |
| 密码与注销 | 页面改密撤销两设备会话；新密码登录后注销，旧令牌被拒绝                                                           |
| 重启与断网 | 后端记录、登录态、未消费票据保留；后端离线时 AI 排队，AI 重启保留队列且不自动采集，显式重启任务后补传            |
| 数据库升级 | 完成业务写入后再次运行迁移，保留既有数据                                                                         |
| 容器专有   | Nginx 静态文件与 HTTP/WS 代理、健康依赖、AI 卷持久化、PostgreSQL 自定义备份恢复到新库并逐行核对                  |

边界验证另由后端测试覆盖：权限交集、并发与审计事务回滚、AI 低分与非法过滤、稳定幂等回执、带时区的 `[from,to)`、课堂提交时段、CSV 引号/换行/公式、一次性票据跨进程消费与失效、AI 代理超时未知结果。客户端演示与受控 HTTP 浏览器用例另行运行，不能代替上述真实链路。

## 验证边界

本地进程模式已在 PostgreSQL 17、Python 3.12、Node.js 24、Playwright Chromium 下通过完整链路；类型检查、生产构建及前后端业务测试通过。Compose 配置已通过解析；当前本地环境没有容器运行时，不能认定本地容器部署已通过。CI 的 `system-acceptance` 执行本地进程链路，`container-acceptance` 执行容器链路及备份恢复；具体提交的通过状态以对应 Actions 结果为准。
