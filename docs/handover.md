# 本地验收与演示视频交接说明

接收环境需要从源码独立启动系统，完成学生、教师、管理员和摄像头 AI 的业务验收，再录制 5～8 分钟的演示视频。客户端交付形态为浏览器 Web，使用回环或局域网 IP，不需要 Android 安装包或域名。已有验证范围与限制见 [项目验证报告](project-verification.md)。

## 1. 交接范围与运行材料

| 内容            | 位置与用途                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------- |
| 源码与共享接口  | `apps/admin`、`apps/client`、`services/backend`、`services/ai`、`packages/contracts`                    |
| 数据库          | PostgreSQL 17；`infra/database/001` 至 `008` 按顺序迁移                                                 |
| 本机安装与启停  | [Windows 本地部署](local-deployment.md)                                                                 |
| 管理端操作      | [管理员注册及认证](backend-auth.md)、[管理操作入口](admin-management.md)                                |
| 业务接口        | [API 契约](api-contract.md)，启动后的 `http://127.0.0.1:8000/docs`                                      |
| AI 图片与摄像头 | [图片 API](image-api.md)、[摄像头实验](camera-api.md)                                                   |
| 自动化验收      | [系统验收](system-acceptance.md)、[客户端验收](client-acceptance.md)、[后端验收](backend-acceptance.md) |

接收环境自行创建虚拟环境、安装 Node.js 依赖和 PostgreSQL，并配置自己的数据库账号、两个不同的 AI 服务令牌和可用的 DeepSeek 密钥。这些配置、运行数据库、日志及原始影像不在源码仓库中。`.local` 内的部署工具和历史运行产物不是新克隆仓库的必备文件，标准运行步骤以部署文档为准。

## 2. 新环境启动顺序

### 获取源码和依赖

```powershell
git clone https://github.com/pyrrolys1ne/Emoji-Based-Classroom-Mood-Checker-System.git
Set-Location Emoji-Based-Classroom-Mood-Checker-System
git switch main
git pull --ff-only
git rev-parse --short HEAD
npm ci
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r services/backend/requirements-dev.txt
.\.venv\Scripts\python.exe -m pip install -r services/ai/requirements-camera.txt
```

已有仓库时先保留未提交修改，再同步 `main`；已有 `.venv` 时复用并更新所需依赖。推荐 Node.js 24、Python 3.13、PostgreSQL 17，摄像头模式使用 OpenCV 和 DeepSeek API，无需下载 DeepFace 权重。

### 数据库与配置

按 [本地部署第 2～3 节](local-deployment.md#2-准备-postgresql) 初始化或复用 PostgreSQL，创建业务数据库，并配置：

| 文件                     | 必须核对                                                                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `services/backend/.env`  | 正确的 PostgreSQL URL；精确的浏览器来源；两个不同的 AI 令牌；`MOOD_AI_BASE_URL=http://127.0.0.1:8001`；`MOOD_ALLOW_SIMULATED_AI=false` |
| `services/ai/.env`       | `AI_BACKEND_URL=http://127.0.0.1:8000`；两组令牌与后端分别一致；仅服务端配置 `DEEPSEEK_API_KEY`                                        |
| `apps/admin/.env.local`  | `VITE_DATA_MODE=api`、`VITE_API_BASE_URL=/api`、后端代理地址                                                                           |
| `apps/client/.env.local` | `VITE_DATA_MODE=api`、`VITE_API_BASE_URL=/api`、后端代理地址；`VITE_ADMIN_URL` 留空以沿用当前主机                                      |

在仓库根目录执行迁移、生成首个管理员注册邀请码并构建：

```powershell
$env:PYTHONPATH = 'services/backend'
.\.venv\Scripts\python.exe -m app.db.migrate
.\.venv\Scripts\python.exe -m app.cli.create_admin_invite --expires-in-hours 24
npm run build
```

邀请码仅供获授权人员注册，首次使用后失效；生成结果不要录入演示视频。已有管理员可登录后从“用户管理 → 邀请管理员”生成邀请码。系统没有可直接复用的默认管理员密码。

### 启动四个进程

四个终端均以仓库根目录为工作目录，分别执行：

```powershell
# 终端 1：正式后端
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir services/backend --host 127.0.0.1 --port 8000 --no-access-log
```

```powershell
# 终端 2：独立 AI 服务
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir services/ai --host 127.0.0.1 --port 8001 --no-access-log
```

```powershell
# 终端 3：管理端
npm exec --workspace @mood/admin -- vite preview --host 127.0.0.1 --port 5173 --strictPort
```

```powershell
# 终端 4：客户端
npm exec --workspace @mood/client -- vite preview --host 127.0.0.1 --port 5174 --strictPort
```

管理端为 `http://127.0.0.1:5173`，客户端为 `http://127.0.0.1:5174`。登录页进入“管理员注册”，使用邀请码创建账号后登录。确认管理端显示“API 模式”“实时通道已连接”，后端 `/api/ready` 和 AI `/health` 返回成功。

同一局域网跨设备使用时，按 [IP 访问配置](local-deployment.md#局域网-ip-访问) 仅调整两个 Web 端的监听、浏览器来源和防火墙。其他设备使用部署电脑的 IP；`127.0.0.1` 始终指向访问者自己的电脑。摄像头始终由运行 AI 服务的电脑读取，不是学生或教师浏览器所在设备的摄像头。

## 3. 本地测试数据

使用独立实验数据库及合成账号，不导入真实学生资料。建议准备以下数据，密码自行设置并单独保管：

| 数据         | 建议内容                                                                   |
| ------------ | -------------------------------------------------------------------------- |
| 管理员       | 一个已获授权的账号；另备一个未使用的邀请码用于展示管理员注册               |
| 教师         | `demo_teacher_a`、`demo_teacher_b`，均通过公开教师申请和管理员审批获得身份 |
| 学生         | `demo_student_a`、`demo_student_b`                                         |
| 课程／课堂 A | 教师 A、班级 A，只安排学生 A                                               |
| 课程／课堂 B | 教师 B、班级 B，只安排学生 B                                               |

演示课堂的起止时间必须覆盖测试和录制时刻，例如开始设为当前时间前 5 分钟、结束设为 1 小时后。已开始或已有记录的课堂不能再修改课程、任课教师和起止时间；录制延期时新建课堂，不修改历史记录规避约束。

在新建的验收课堂 A 中由学生 A 提交开心、平静、困惑各一条，在课堂 B 中由学生 B 提交低落一条。未产生其他反馈时，手动来源应为 A 三条、B 一条、合计四条。重做操作会增加记录，比较统计前先确定课堂、时间范围与实际记录数。

管理员、教师、学生使用独立浏览器会话或不同浏览器配置文件，避免同一会话切换账号影响比较。教师 B 用于验证不能查看课堂 A，学生 B 用于验证不能提交课堂 A 的反馈。

逐项记录“通过／失败／未执行”，附版本、环境、实际结果及必要截图。API 成功和数据库真实保存是通过依据，页面存在或演示数据可见不能代替业务验收。

| 编号 | 检查操作             | 通过条件                                                                                       |
| ---- | -------------------- | ---------------------------------------------------------------------------------------------- |
| L01  | 启动及健康检查       | 两个 Web 端为 API 模式；正式后端和 AI 健康；数据库迁移至 008；实时连接建立                     |
| L02  | 管理员注册           | 有效邀请码创建新管理员并能登录；同一邀请码再次注册不同账号被拒绝；无效邀请码不创建账号         |
| L03  | 学生注册、登录与改密 | 正常注册登录；错误密码和不合规输入被拒绝；改密后新密码可用，旧会话失效                         |
| L04  | 教师申请审批         | 待审批教师不能登录；管理员批准后可登录；教师不能生成管理员邀请码或进入管理写操作               |
| L05  | 课程与课堂           | 管理员创建课程和课堂、指定已批准教师，刷新后资料保留                                           |
| L06  | 学生安排             | 课堂名单保存后学生只看到被安排课堂；名单改变不删除历史反馈                                     |
| L07  | 表情反馈及历史       | 课堂时段内提交成功，来源 MANUAL；刷新、退出重登后仍能查到相同记录                              |
| L08  | 跨端一致             | 学生 A 的记录在任课教师、管理员记录列表和 CSV 中一致；学生 B／教师 B 不能越权读取课堂 A 的数据 |
| L09  | 实时看板             | 保持教师或管理员看板打开，学生新增反馈后自动更新汇总；不以手动刷新代替实时效果                 |
| L10  | 多维统计             | 课程、班级、时间段、MANUAL／AI／ALL 筛选有效；分布与分组、时间桶总数一致；分页不截断统计       |
| L11  | CSV 导出             | 管理员导出成功，内容与相同筛选的记录一致；中文正常，教师不能导出管理员 CSV                     |
| L12  | 真实摄像头 AI        | 按第 5 节验证摄像头 → 远程推理 → 结构化入库，停止后释放设备；不能仅用公开图片分析证明此项      |
| L13  | 失败与恢复           | 断网／后端不可用时不提示反馈保存成功；AI 结构化队列保留，恢复后按幂等键补传；系统验收覆盖此项  |
| L14  | 重启与数据保留       | 正常停止采集和服务后重启，账号、课堂与历史保留；AI 不自动恢复采集                              |
| L15  | IP 访问              | 若采用跨设备演示，另一台设备通过部署电脑 IP 登录、提交反馈，教师管理端链接和实时连接均正常     |

## 5. 真实摄像头预演

1. 确认 AI 服务运行在装有摄像头的电脑上，安装摄像头依赖，配置可用 DeepSeek 服务端密钥、网络和账户余额。
2. 管理员进入“AI 集成”，关联正在进行的验收课堂，选择“本机摄像头 + DeepSeek API”。摄像头编号从 0 尝试，按实际驱动确定，关闭其他占用设备的程序。
3. 建议先设采样间隔 10 秒、阈值 0.5、最多采样 1 次、最长运行 120 秒。明确允许发送采样帧后再启动；保持清晰光照和可见人脸。
4. 核对实际采样次数、API 调用次数、上报／过滤／失败／待重试数、停止原因。无人脸、未知类别或低于阈值可能不会产生课堂记录，这是过滤结果，不能伪造一条成功记录。
5. 若有接受结果，在情绪记录中筛选 AI，核对关联课堂、时间、匿名用户、`simulated:false`、提供方 DeepSeek 和 `confidenceKind:self_reported`；统计切换 AI／全部来源后能查到，CSV 保留对应分数类型。
6. 达到上限或点击停止后核对状态和设备释放；重启服务不得自动开摄像头。一次采样可能检出多张人脸，采样次数、记录条数和去重学生数不能混用。

默认不保存原始帧、视频或人脸特征，队列只保存匿名结构化结果。自评分用于过滤，未经校准，不能描述为准确率、心理状态、专注程度或学习效果。专注和困惑只作为手动选项。

正式录制前先完成真实调用预演。遇到远程限流、超时、余额或网络错误，先核对状态再决定是否重新启动，避免重复付费调用。外部服务不可用时应修复或调整录制时间；模拟输入、历史截图和公开图片分析分别标明用途，不能替代真实摄像头入库验收。

## 6. 自动化验证命令

前端与 Python 基础检查：

```powershell
npm run typecheck
npm run test:admin
npm run test:client
npm run build
.\.venv\Scripts\python.exe -m pytest services/ai/tests -q
.\.venv\Scripts\python.exe -m pytest services/integration/tests -q
```

联调测试需要另安装 `services/integration/requirements.txt`。后端完整测试与系统验收使用另行配置、具备创建数据库权限的测试账号。连接指向专用测试 PostgreSQL，不使用真实业务数据库账号或将连接串录入视频：

```powershell
$env:MOOD_TEST_DATABASE_URL = 'postgresql+psycopg://<测试账号>:<URL编码后的密码>@127.0.0.1:5432/postgres'
.\.venv\Scripts\python.exe -m pytest services/backend/tests -q
npx playwright install chromium
npm run test:system
```

测试创建并清理随机临时库；后端出现“跳过”不能当作真实数据库通过。系统验收使用明确标记的模拟 AI，不打开摄像头或调用付费服务。

客户端兼容性及受控响应浏览器测试，可统一安装到本地忽略目录后运行：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.local/browsers'
npx playwright install chromium firefox
npm run test:e2e --workspace @mood/client
npm run test:system
```

同一终端中的 `PLAYWRIGHT_BROWSERS_PATH` 对安装和执行保持一致。该组浏览器测试覆盖桌面、手机视口和错误响应，使用演示或受控 HTTP；真实跨端验收以 `test:system` 为准。自动化测试和录制使用不同数据环境；录制前按部署配置重新构建，并正常启动自己的验收数据库与四个服务。

## 7. 演示视频脚本

建议 MP4、1080p、清晰中文解说，总时长 5～8 分钟。提前完成依赖下载、环境配置、真实 API 预演，另备隔离账号和课堂用于权限比较。下面约 7 分钟的顺序可根据实际操作节奏调整：

| 时间      | 画面与操作                                            | 需要说明的事实                                                      |
| --------- | ----------------------------------------------------- | ------------------------------------------------------------------- |
| 0:00—0:25 | 展示浏览器客户端和管理端入口                          | 浏览器 Web、正式后端和 PostgreSQL；本机 IP 运行，页面为 API 模式    |
| 0:25—1:05 | 使用预先生成的邀请码完成管理员注册并登录              | 一次性授权注册，不公开自行提权；邀请码输入区遮挡                    |
| 1:05—1:50 | 学生／教师注册，管理员批准教师，教师登录              | 角色不同，教师审批前无法使用业务功能                                |
| 1:50—2:35 | 管理端创建课程课堂、指定教师并安排学生                | 真实保存名单；课堂时间覆盖录制时刻                                  |
| 2:35—3:25 | 学生选择表情、提交、查看历史并刷新                    | 记录来源 MANUAL，刷新后仍存在                                       |
| 3:25—4:05 | 任课教师查看记录和看板，学生再提交一次                | 同一反馈跨端一致，看板自动更新；其他教师不见无关课堂                |
| 4:05—5:05 | 管理员启动一次真实摄像头 API 采样，核对停止及 AI 记录 | 显示真实上报结果、匿名来源与自评分；等待可合理剪辑并标注            |
| 5:05—6:05 | 按课程、班级、时间及来源切换统计，导出并打开 CSV      | 筛选范围一致、MANUAL／AI 区分，中文导出可读                         |
| 6:05—6:45 | 展示改密／退出与后端重启后的历史                      | 旧会话失效，真实持久化；停止采集后再重启                            |
| 6:45—7:15 | 展示结果并说明边界                                    | 不保存原始影像；模型自评分不代表准确率，外部 API 有可用性与延迟限制 |

录制中的改密会撤销该账号全部会话，安排在该角色演示结束后。重启只需停止并重新启动后端即可展示历史持久化，不必在视频中重新安装或构建。完整数据库重启、备份恢复和跨设备检查应在预演验收中完成。

系统的时间趋势图当前展示反馈条数随时间变化，情绪构成另有分布图，课程／班级另有汇总表。解说按实际图义表述，不将其说成“各情绪占比随时间变化曲线”。

录屏关闭通知和无关窗口，保证表格、图表、错误提示可读；遮挡密码、邀请码、访问令牌、DeepSeek 密钥、数据库连接凭据和个人机器路径。展示系统状态及结构化结果即可，不录入原始人脸帧。
