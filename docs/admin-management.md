# 管理端数据维护

管理员在正式 API 模式下维护教师申请、课程、课堂与学生资料。管理端保留 MVC 分层：页面负责展示，控制器负责异步加载及保存状态，模型封装可选身份和时间规则，仓储调用既有后端接口。演示及独立联调模式只显示功能说明，不模拟这些维护操作成功。

## 操作入口

登录页的“管理员注册”通过一次性邀请码创建新账号。已有管理员在“用户管理 → 邀请管理员”生成邀请码，可选 1 小时、24 小时、3 天或 7 天；邀请码注册成功后失效，离开页面不保存在浏览器存储中。首次部署由服务端命令生成邀请码，详见 [账号认证](backend-auth.md)。

| 入口                | 能力                                     | 接口                                                                               |
| ------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------- |
| 教师审批            | 按状态查看申请、批准或驳回、填写审核说明 | `GET /api/admin/teacher-applications`、`PUT /api/admin/teacher-applications/{id}`  |
| 课程课堂 → 课程目录 | 新建、编辑课程名称及默认教师             | `GET /api/admin/courses`、`POST /api/admin/courses`、`PUT /api/admin/courses/{id}` |
| 课程课堂 → 课堂会话 | 新建、编辑课堂、指定实际任课人           | `POST /api/admin/sessions`、`PUT /api/admin/sessions/{id}`                         |
| 用户管理 → 编辑资料 | 维护学生学号、姓名、所属班级             | `PUT /api/admin/users/{id}/student-profile`                                        |
| 课堂安排            | 替换课堂学生名单                         | `POST /api/admin/sessions/{id}/schedule`                                           |

教师界面不展示新增管理入口，直接访问对应路由会返回课堂概览；后端仍独立执行管理员鉴权，前端隐藏不能替代权限校验。

## 数据规则

- 教师审批仅操作待审核且启用的申请账号，提交后刷新申请和用户身份。已处理申请不再提供审批操作；并发审批冲突保留错误提示，不自动重放请求。
- 课程和课堂的教师选项只包含启用且已批准的教师。修改课程默认教师不会转移已有课堂及历史记录的权限。
- 新课堂不自动安排学生；所属班级修改也不改变名单。课堂保存后通过“课堂安排”单独添加学生。
- 已开始或存在已加载记录的课堂锁定课程、实际任课人和起止时间，允许更正教室与班级。即使页面无法预知并发新增记录，服务端仍执行最终限制；收到 409 时保留表单，请刷新核对后调整。
- 时间输入按浏览器本地时区解释，提交带时区时间戳。未变更时间保留原值，避免秒和微秒精度丢失导致误改历史课堂。
- 学生资料留空表示显式清除，未开放角色、状态、邮箱及密码修改。学号冲突显示后端错误，保留原输入；教师申请账号不作为普通学生编辑或新安排。旧名单中的不可安排账号允许移除。
- 保存期间禁用表单及关闭按钮，防止重复点击；仅在收到有效成功回执后显示保存成功。失败不自动重试写操作，无效回执提示刷新核对结果。

## 验证

`npm run test:admin` 覆盖维护仓储、角色和模式隔离、审批冲突、学号冲突、清空字段、锁定课堂时间精度及重复提交。组件测试使用受控接口替身；正式 PostgreSQL 和跨端链路按 [系统验收](system-acceptance.md) 单独验证。完整后端约束见 [课程课堂说明](backend-classrooms.md) 与 [账号审批说明](backend-auth.md)。
