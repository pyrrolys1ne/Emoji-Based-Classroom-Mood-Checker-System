# 客户端联调交接说明

`apps/client` 已提供 React 学生端演示页面，可选择表情并查看本次页面会话的记录。目前未接入账号、课堂与提交接口，刷新后演示历史消失，与管理端数据不互通。

## 客户端需要完成的工作

| 优先级 | 功能                 | 接口与要求                                                                                                                |
| ------ | -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 1      | 注册、登录与个人信息 | 对接 `POST /api/auth/register`、`POST /api/auth/login`、`GET /api/users/me`；校验输入、处理登录过期，不开放管理员自助注册 |
| 1      | 课堂列表与选择       | 对接 `GET /api/sessions`，展示当前用户可访问的课堂；提交必须关联真实课堂编号，不能继续使用固定演示课程                    |
| 1      | 提交表情             | 对接 `POST /api/emoji`，请求为 `{sessionId,emotion}`；等待服务端确认后显示成功，请求期间禁用重复点击，失败保留选择并提示  |
| 1      | 个人历史             | 对接 `GET /api/emoji/history?sessionId=...`；查询当前学生记录，支持课堂筛选，刷新或重新登录后能从后端恢复                 |
| 2      | 修改密码与退出       | 对接 `PUT /api/auth/password`、`POST /api/auth/logout`；退出清理登录态及个人缓存，密码变更后的会话处理与后端一致          |
| 2      | 移动端与异常状态     | 完成手机布局、加载中、空列表、断网、无权限和会话过期提示；明确区分演示模式与真实 API 模式                                 |

教师查看所授课堂历史与基础统计的需求也需覆盖，可复用管理端已有教师视图；教师入口和登录衔接方式与后端对齐，不能让教师读取全局用户或其他课堂数据。

## 对接约束

- 沿用 `packages/contracts` 的情绪枚举和类型；学生手动提交不携带用户编号、AI 来源或 AI 分数，由后端依据登录身份写入 `MANUAL` 记录。
- 统一响应为 `{code,message,data}`，成功 `code: "OK"`；携带用户认证令牌，收到 401 后清理失效登录态并提示重新登录。服务端仍须强制校验身份与数据范围。
- 将页面展示、交互状态与 API 仓储分层，可采用 MVVM 或 MVP 职责划分；不要把所有请求与业务规则堆在 `main.tsx`。
- 正式后端仍有占位接口；当前独立联调服务仅提供管理员／教师合成登录，不能视为完整学生后端。与后端确认学生账号、可见课堂及接口后再验收，不以页面本地历史冒充入库成功。
- 客户端不需要调用 DeepSeek、控制摄像头或保存 AI 服务密钥。接口字段或分页方式变化时，同步 [API 契约](api-contract.md) 与调用方。

## 联调交付与通过标准

提供运行及 API 地址配置说明、测试用例和构建结果。浏览器端可通过 `npm run dev:client` 启动，构建使用 `npm run build --workspace @mood/client`。

优先打通“学生登录 → 选择课堂 → 提交表情 → 个人历史查询”。验收时再验证教师能查看相关记录、管理员能在看板和导出中看到该记录；两个学生不能互查历史，断网不能提示成功，刷新后记录仍存在，退出后不能继续访问个人数据。
