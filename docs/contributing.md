# 团队协作约定

组长同时负责管理端。其他成员在分工确认后选择后端、客户端、AI 或测试文档任务。团队可调整框架技术选型，但变更先同步接口和运行说明。

## 分支与提交

- `main` 保存已验证可构建的基础版本。
- 功能分支建议使用 `feat/admin-*`、`feat/backend-*`、`feat/client-*`、`feat/ai-*`，文档使用 `docs/*`。
- 每人使用自己的真实 Git 身份提交；不得伪造其他成员贡献记录。
- 功能完成后创建拉取请求，说明实现内容、验证方式和未完成事项，由组内审查后合并。
- 本轮初始化按用户授权直接推送 `main`；后续业务开发使用功能分支。

## 修改边界

- 管理端：`apps/admin`，组长负责。
- 客户端：`apps/client`。
- 后端与数据库：`services/backend`、`infra/database`。
- AI 服务：`services/ai`。
- 共享类型与 API 契约：修改前协调所有调用方，变更后同步更新后端模型、前端类型与文档。
- 保持 `AGENTS.md` 中的中文要求、决策和完成记录与实际项目一致。

## 提交前检查

执行前端构建与后端测试；修改配置时同步 `.env.example` 和 README。不得提交 `.env`、服务令牌、真实用户隐私、原始人脸图像或视频；生成物与依赖目录已在 `.gitignore` 排除。
