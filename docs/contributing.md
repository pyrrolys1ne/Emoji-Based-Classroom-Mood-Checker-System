# 开发与提交规范

## 提交方式

- 在 `main` 分支工作，提交后直接推送到 `origin/main`。
- 提交前同步远程变更并检查差异，保留已有修改。
- 不创建功能分支，不以拉取请求作为日常提交步骤。
- 使用真实 Git 身份，提交信息描述具体的代码或文档变化。
- 不强制推送或改写历史，除非有明确要求。

## 模块边界

- 管理端：`apps/admin`。
- 学生端：`apps/client`。
- 正式后端：`services/backend`。
- AI 服务：`services/ai`。
- 开发联调参考服务：`services/integration`。
- 数据库和容器配置：`infra`。
- 共享类型与接口：`packages/contracts`、`docs/api-contract.md`。

接口变更需同步调用方、请求模型、数据库迁移与文档。参考服务不作为正式后端部署。

## 内容与验证

- 文档和注释仅记录项目用途、配置、业务规则、接口与必要的实现理由。
- 不写入聊天记录、个人分工、执行日志、个人机器路径、账户环境或实际凭据。
- 不提交 `.env`、运行数据库、依赖目录、日志或原始人脸图像、视频。
- 按修改范围执行构建和测试；配置变化同步环境变量示例与运行说明。
- 维护 `AGENTS.md` 中的开发规范与技术约束，不将其用作对话日志。
