# 客户端测试与验收清单

本清单覆盖学生完整流程和教师基础页，包含客户端独立测试及真实后端联调。实际执行结果和未完成项见 [客户端验证结果](client-test-report.md)，本文件保留完整验收标准。

功能范围参见 [客户端交接](client-handoff.md)，请求与依赖参见 [客户端对接约定](client-integration.md)。mock、独立参考服务和正式后端的结果分别记录，只有真实链路通过才能认定集成完成。

## 独立客户端测试

| 编号 | 检查内容           | 通过条件                                                                                                      |
| ---- | ------------------ | ------------------------------------------------------------------------------------------------------------- |
| C01  | 注册和登录表单     | 必填与已约定格式校验；错误可理解；无管理员自助提权；密码不进入 URL、日志或持久业务缓存                        |
| C02  | 会话恢复和身份切换 | 使用本人信息恢复角色；401 清理身份和缓存；旧响应不能恢复已退出账号的数据                                      |
| C03  | 改密和退出         | 旧密码错误保留正确状态；成功后按合同处理会话；服务端注销失败有明确提示                                        |
| C04  | 课堂选择           | 使用后端 ID；无课堂、失败和无权限有对应状态；快速切换以最后一次选择为准                                       |
| C05  | 手动提交           | 请求仅 sessionId、emotion；双击只发一次；OK 后更新历史；失败保留选择；未知结果不自动重放写请求                |
| C06  | 个人历史           | 课堂筛选正确；刷新从仓储恢复；无数据和请求失败可区分；换号不串数据                                            |
| C07  | 教师基础页         | 所授课堂、相关学生历史和全量基础统计；匿名 AI 不归属某个学生；不请求管理员全局用户目录                        |
| C08  | HTTP 与合同        | 方法、路径、小驼峰、九种情绪、包装与时间一致；异常 JSON、非 JSON、401、403、409、422、501、503 和超时按约处理 |
| C09  | 数据源真实性       | mock 明确标识；API 失败不转为演示成功；分页或截断数据不被当成全量统计                                         |
| C10  | 状态和可访问性     | 主要页面覆盖 loading、empty、error、offline、permission-denied、expired、success；键盘可达、标签和焦点明确    |

采用适合实际实现的业务／状态、组件、HTTP mock 和浏览器测试。测试重点是可观察行为与错误边界，不以机械覆盖率或快照数量替代验证。实现时将客户端测试接入独立 CI，并保留现有模块检查。

## 真实后端与跨端验收

仅对隔离开发环境和合成账号执行；数据重置使用后端提供的方法。服务端缺陷由对应维护模块修复，客户端承担复现与回归。

| 编号 | 流程                     | 通过条件                                                                                                             |
| ---- | ------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| E01  | 学生注册、登录、刷新恢复 | 创建真实账号并取得有效身份；刷新后仍可正确恢复                                                                       |
| E02  | 教师注册与角色授予       | 按已确认的教师注册／申请和服务端授予流程取得角色；预置教师只用于基础页联调，不代表教师注册通过；不能篡改请求自行提权 |
| E03  | 管理员安排 → 学生课堂    | 安排结果真实保存；两名学生按名单看到各自课堂；任意 sessionId 仍受后端校验                                            |
| E04  | 提交 → 个人历史          | 真实记录属于登录学生，来源 MANUAL；刷新和重新登录仍存在                                                              |
| E05  | 学生 A／B 隔离           | 改参数、切课堂或换账号仍不能互查历史，页面不残留另一个人的数据                                                       |
| E06  | 教师任课隔离             | 仅看所授课堂及相关学生；非任课课堂的历史和统计被服务端拒绝                                                           |
| E07  | 提交时段和重复策略       | 课前／课后按合同处理；双击及响应丢失场景遵循确认后的去重／查证规则                                                   |
| E08  | 断网和未实现接口         | 不提示已保存；保留选择；恢复网络后按规则查证结果，不重复创建记录                                                     |
| E09  | 改密和退出               | 服务端会话按合同失效或保留；注销撤销相应会话；本地不再展示个人数据                                                   |
| E10  | 教师统计                 | 与相同课堂、范围和来源的全量记录一致，分母明确；匿名 AI 与个人手动记录不混淆                                         |
| E11  | 管理端一致性             | 同一条手动记录能被任课教师、管理端看板和 CSV 查到；记录 ID、课堂、来源和时间一致                                     |
| E12  | 重启持久性               | 在测试环境受控重启后端后记录仍存在；不使用页面内存或模拟数据证明持久化                                               |

## 视觉与使用检查

- 自动化以 Chromium 为主，核心流程增加 Firefox 兼容检查；手机视口检查与真机浏览器检查分别记录，视口模拟不冒充真机验证。
- 实际检查 1440×900 桌面与 390×844 手机截图，并检查 320 像素窄屏；记录实际浏览器与尺寸。
- 学生首页优先呈现课堂、表情和提交；教师页优先呈现课堂筛选、历史与基础分布。
- 字号、间距、按钮、表单和颜色一致；无重叠、遮挡、横向溢出、截断标题或不可点击区域。
- 长课程名、长用户名、空列表、错误及加载状态均可读；表情有文字，图表不只依赖颜色。
- 用户页面不出现 API 地址、JSON、技术教程和调试日志；演示模式仅保留必要的清晰标识。
- 键盘能完成主要流程，焦点可见，表单有标签，状态提示对辅助技术可读。

## 构建与协作检查

客户端类型和构建命令为 `npm run typecheck --workspace @mood/client`、`npm run build --workspace @mood/client`；业务测试运行 `npm run test:client`，浏览器测试运行 `npm run test:e2e --workspace @mood/client`。浏览器安装、数据源和完整运行方法见 [运行与维护](client-development.md)。

从依赖锁文件安装后，运行客户端类型、构建、业务和浏览器测试。共享类型变更时增加受影响前端的类型检查和构建；根依赖与 CI 变化按实际影响验证。合并或冲突处理后，重新运行受影响检查。

交付时确认 main 的本地与已授权远端提交、现役 hooks、适用 CI 终态；在干净检出中按说明复现启动和核心流程。真实后端 E2E 在合适的隔离环境执行，不把仅 mock 的 CI 结果解释为服务器权限已验证。

## 结果与缺陷记录

测试报告记录实际提交、执行日期、浏览器／环境、实际命令和结果。截图、日志、追踪文件按仓库忽略规则本地保存并脱敏；报告只引用可分享的结果，不提交密码、令牌、私人路径或原始个人数据。

未通过或未执行项写明编号、复现、预期与实际、影响、维护模块、阻塞原因和下一步。不能把“未执行”“等待后端”和“通过”混在一起。

本轮完整验收需要：约定功能完成、独立测试通过、真实链路及关键权限通过、视觉检查通过、构建可复现、文档与实现一致，以及适用的 Git 和 CI 结果可核对。客户端独立完成但后端不可用时，交付实现和明确等待项，真实集成验收保持未完成。
