# 摄像头与 DeepSeek 实验

该模式在运行 AI 服务的机器上读取摄像头，将单帧编码为 JPEG 发送至 DeepSeek `deepseek-flash`，过滤后仅将匿名结构化结果写入关联课堂。浏览器不直接持有 API 密钥，也不采集视频。它与本地 DeepFace 摄像头模式、公开图片样本测试相互独立。

## 安装与启动

```powershell
.\.venv\Scripts\python.exe -m pip install -r services/ai/requirements-camera.txt
npm run dev:integration
```

在 `services/ai/.env` 配置 `DEEPSEEK_API_KEY`。该模式需要 OpenCV 和基础 AI 依赖，不需要 DeepFace、TensorFlow 或本地模型权重。若 AI 端口冲突，可在启动前设置 `MOOD_AI_PORT`。

管理员登录管理端，在“AI 集成”选择关联课堂与“本机摄像头 + DeepSeek API”，填写设备编号，勾选将采样帧发送至 DeepSeek，再启动采集。设备编号通常从 0 开始；设备顺序由系统和驱动决定。教师没有启停权限。

默认间隔 10 秒、最多 5 次、最长 120 秒；服务端要求间隔至少 5 秒，上限可配置为 1—60 次和 10—600 秒。每次启动都重新从零计数。摄像头失败会显示连接错误并在时间上限内重连；API 错误停止本轮，不自动重新调用付费推理。

API 模式每次采样重新打开设备，读取后立即释放，再请求远程推理，避免低频采样时积压历史帧。原始帧与 JPEG 只在内存中处理，不写磁盘，不加入重试队列。若设备被其他程序占用或系统禁止访问，需解除占用或在系统隐私设置中允许应用访问；服务不修改系统权限。

## 状态、停止与记录

页面显示采样次数、API 调用次数、最近结果与耗时、上报与过滤计数、待重试数和停止原因。无脸返回空结果；未知类别和低自评分不会入库。模型自评分不是经过校准的概率，阈值只用于筛选，不能据此判定准确率、心理状态、专注程度或学习效果。

达到次数或时长上限后停止新采样；正在执行的设备读取或 API 请求可能延后结束。点击停止后不启动新请求，进行中调用返回结果被丢弃。已经入库的记录保留，未发送的结构化结果留在持久化队列中；重启采集后继续发送。停止状态不等于已有队列已清空。

入库包含课堂、采样时间、表情、自评分、设备编号和 `source: AI`、`simulated: false`、`inferenceProvider: DeepSeek`、`confidenceKind: self_reported`。用户编号为空，不做人脸身份识别或跨帧跟踪。记录列表显示“AI · DeepSeek”和“自评分”，CSV 保留提供方与分数类型。条数代表采样人脸结果，不能视为去重学生数。

本地联调使用合成课堂和 SQLite，真实摄像头结果仍属于实验数据。正式部署需完成正式后端契约、权限和数据库集成，并依据部署场景决定是否允许将真实课堂影像发送至远程服务；默认不自动采集或远程发送。

## 验证边界

自动化测试使用设备与模型替身，验证采样上限、停止、过滤、设备释放、匿名载荷、自评分元数据与幂等，不会在 CI 中打开摄像头或调用付费 API。实际设备读取、网络延迟、无脸和遮挡条件需在目标环境检查。模型效果评估需要有标注、覆盖多种表情的数据集，少量摄像头实验不能证明准确率。
